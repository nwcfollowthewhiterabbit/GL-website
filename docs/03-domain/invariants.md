# Инварианты

1. ERPNext остается master для SKU, price, stock, Customer и sales documents.
2. Website quote id не создает более одного Quotation.
3. Customer account не возвращает document вне разрешенных Customer links.
4. Неверный login не раскрывает существование email.
5. Password хранится только как salted `scrypt` hash.
6. Cardholder data никогда не проходит через website backend.
7. Payment amount, currency и ERP reference фиксируются до HPP redirect.
8. Повторный verified callback не создает второй ERP payment effect.
9. Payment/indexing выключены по умолчанию до явного approval.
10. Website deploy не изменяет ERP runtime.
11. Регистрация создаёт credential только после проверки одноразового email token;
    повторная регистрация не заменяет пароль существующего credential.
12. Reset token привязан к версии credential и не включает отключённый доступ.
13. Запрос котировки использует Customer/email проверенной сессии, серверные цены
    и весь валидный набор строк; некорректные строки не отбрасываются молча.
14. Текущий release не создаёт Sales Order, Invoice, Payment Entry или card session
    при отправке корзины; все запросы ожидают проверки sales.

## Продажные упаковки котировки

Строка выбора задаётся парой (SKU, продажная UOM). Количество — число выбранных
упаковок. Каталог и котировка используют действующую общую цену в FJD из
разрешённого прайс-листа, с датой действия по ERP и коэффициентом из карточки
Item. При конфликтующих равноприоритетных ставках или отсутствующем коэффициенте
вариант исключается из продажи. Коэффициент не вычисляется из текста названия.
При отправке ERP проверяет действующую ставку и доступность упаковки. Корзина хранит артикул, упаковку и количество. Раньше сохранённая строка
без подтверждённой UOM может быть восстановлена автоматически только при
единственной допустимой упаковке. ERP получает UOM, коэффициент, количество,
ставку и две самостоятельные строки для двух упаковок одного артикула.
Поле Item Price.packing_unit задаёт кратность заказанного количества в этой UOM.
Если оно равно шести, допустимы 6, 12 и последующие кратные количества по цене
за одну UOM. Интерфейс использует этот шаг, API повторяет проверку ERPNext
check_packing_list до создания документа.
